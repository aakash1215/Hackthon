Track-Specific Rules

Track 1: Open Weight AI & Open Source Tools
1.1. Key definitions:
● Open source: the project's source code is public and carries a license that allows others
to use, modify, and share it. Common choices include MIT, Apache-2.0, and GPL-3.0.
The OSI license list includes more options.
● Open-weight model: the trained model weights are available to download or run under
the model provider's terms. Open-weight does not automatically mean that every part of
a model is open source, so teams should name the model and link its license or terms in
the README.
● Small and large language models: for this challenge, a small language model has 10
billion parameters or fewer, while a large language model has more than 10 billion
parameters. Teams are not restricted to any specific model — any open-weight or
open-source model is acceptable, including (but not limited to) models like Qwen, Llama,
Gemma, Mistral, Phi, DeepSeek, and smaller 2–3B parameter models, as well as
open-weight speech models (e.g., Whisper) and vision models. The only constraint is on
closed, proprietary AI APIs (e.g., Gemini API, Anthropic/Claude API, OpenAI API) —
these may not serve as the project's core AI component, per Section 4.5.
1.2. Open-source or open-weight AI must be an important, foundational part of the project — not
a cosmetic addition.
1.3. The final project must be published in a public GitHub repository.
1.4. The README must clearly cite:
● The exact model(s) used, including parameter count.
● A link to the model provider's license/terms of use.
1.5. Use of closed/proprietary AI APIs (e.g., GPT-4, Claude, Gemini via paid API) as the core AI
component is not permitted. Such APIs may only be used for incidental, non-core purposes
(e.g., generating sample test data) and must be disclosed.
